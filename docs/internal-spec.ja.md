# 内部仕様書

[English](internal-spec.md) · [README](../README.ja.md) · [外部仕様書](external-spec.ja.md)

## 概要

CLIは同期先、Markdownの比較基準、ミラーの記録をファイルに保存します。同期先の内容は利用者が指定した実行ファイルに問い合わせます。ローカルのミラーはバックグラウンドのBashプロセスが行います。利用者から見える振る舞いは[外部仕様書](external-spec.ja.md#機能一覧)を参照してください。

## コードの構成

`bin/file-sync`は生成済みの`file-sync.sh`へのシンボリックリンクです。各コマンドはファイル操作に`io.ab`を使います。

| ファイル | 責務 |
| --- | --- |
| [main.ab](../src/main.ab) | 設定の保存先を読み取り、共通の引数を検証して処理を振り分ける。 |
| [targets.ab](../src/targets.ab) | 同期先の読み取りと更新、プラグイン設定の検証、JSONによる通信を行う。 |
| [sync.ab](../src/sync.ab) | Markdownを解析して比較し、バックアップと比較基準を保存する。 |
| [jobs.ab](../src/jobs.ab) | 同期ジョブを読み、1回の同期、ワーカーの開始、状態確認、停止を扱う。 |
| [plugins/local-mirror](../plugins/local-mirror) | ミラーを特定し、監視プロセスの起動、停止、両側のファイルの照合を行う。 |
| [io.ab](../src/io.ab) | パスを解決し、ロックを取得してファイルを置き換える。 |

変更するときはAmberソースを編集し、[配布用スクリプトを再生成](../README.ja.md#ソースからビルドする)します。

## 処理設計

- **F-001 同期先の登録。** ファイルの実パスを求め、設定された実行ファイルでURLを解決します。ロック内でパスとURLの重複を調べ、登録内容が変われば保存します。
- **F-002 Markdownの比較と反映。** 手元のMarkdownを解析し、同期先の内容をプラグインから受け取ります。見出しと本文を取り出し、改行コードと末尾の改行をそろえて比較基準と照合します。`pull`の確認後、書き込みロック内で両側を読み直します。元のファイルをバックアップし、元と同じモードで新しいファイルを書きます。保存した見出しと本文が同期先と一致したら比較基準を更新します。
- **F-003 ローカルファイルのミラー。** ローカルミラープラグインはコピー先の実パスのSHA-256で記録を特定する。各回で元とコピーのハッシュを前回の一致と照合し、置き換えの直前にも転送内容と書き込み先を検証する。

ジョブの監視プロセスは起動時の設定を保持し、各回の実行前に再読込して照合する。`jobs/<名前>/worker.lock` のロックで稼働を判定し、同じディレクトリの `stop` で停止を要求する。同期処理は1回ごとに終了し、競合やエラーがあれば診断を `worker.log` に残して止まる。ローカルの照合は独立してビルドしたプラグインが受け持つ。

## データ

| 保存先 | パス | 内容 |
| --- | --- | --- |
| 設定 | `plugins/<id>.json` | 実行ファイルのパスと設定。 |
| 設定 | `targets.json` | `version: 1`と、パス・プラグインID・URLを含む`targets`配列。 |
| 状態 | `state.json` | `{target, baseline, syncedAt}`の配列。`target`全体をキーとし、`baseline`に`title`と`body`を保存する。 |
| 状態 | `backup/` | `pull`やミラーの逆反映で置き換える前の内容。 |
| 状態 | `mirror/<key>/session.json` | コピー先、反映方向、ファイルの組。各組にはパス、比較基準のハッシュ、問題があればその内容を保存する。 |
| 状態 | `jobs/<name>/worker.log` | 監視プロセスの出力と診断。 |

## プラグインの呼び出し

設定された実行ファイルを直接起動し、標準入力に[リクエスト](external-spec.ja.md#プラグインとの通信)を渡します。標準出力にバージョンと結果を含む応答が1件あることを確かめ、操作ごとに必要な項目を検証します。実行ファイルが非ゼロで終了するか、不正な応答を返すと処理を中断します。

書き込み対応のプラグインには、確認後に両側を読み直してから `write` を送ります。保存済みの応答を受けた後、状態の書き込みロックを取得し、同期先とローカルを再照合して比較基準を記録します。

## 同時実行と復旧

`.targets.lock` は登録とMarkdownの変更、`mirror/<key>/control.lock` はコピー先ごとの照合を直列化する。ジョブの停止要求は実行中のプラグイン呼び出しが終了した時点で処理する。

`.write.lock`は同じ状態ディレクトリを使う比較基準の保存、`pull`によるMarkdownの更新、ミラーの反映を直列化します。登録、ミラー操作、書き込みのロック取得は15秒で打ち切ります。同じディレクトリの一時ファイルに書いてから、ファイル名を変更して保存します。`pull`でMarkdownを更新してから比較基準を保存するまでに中断した場合、バックアップが残り、比較基準は更新されません。再試行前に差分を確認します。

## 設定と権限

[設定と状態の保存先](external-spec.ja.md#終了コードとデータ)は既定で`HOME`の配下です。ファイルの作成には`umask 077`を使います。`pull`ではMarkdownの元のモードを維持し、ミラーのコピーには`cp -p`を使います。プラグインは起動したユーザーの権限で動きます。監視プロセスは起動コマンドの終了後も動き続けます。

## 検証

Amber 0.6.0-alphaで再生成し、同梱のスクリプトと一致することを確かめます。

```sh
amber build --target bash-3.2 --no-proc bshchk src/main.ab - | cmp - file-sync.sh
/bin/bash -n file-sync.sh
```

一時的な設定・状態ディレクトリで[ミラーの実行例](../README.ja.md#使ってみる)を試します。変更が両方向に反映されること、開始時に別内容のコピーを保持すること、監視を停止できることを確かめます。`resolve`と`read`を返すテスト用の実行ファイルで、比較結果、`pull`の確認とバックアップ、`push`での差分表示を確認します。
